# Politique de sécurité

## Signaler une vulnérabilité

**N'ouvrez pas d'issue publique.** Utilisez le signalement privé de GitHub :
onglet *Security* du dépôt, puis *Report a vulnerability*
(<https://github.com/kouratoussaint/safelink/security/advisories/new>).

Indiquez la version concernée (Paramètres › À propos), les étapes pour
reproduire et l'impact estimé. N'incluez pas de données personnelles
réelles.

## Ce que nous nous engageons à faire

| Étape | Délai visé |
| --- | --- |
| Accusé de réception | 7 jours |
| Première évaluation | 14 jours |
| Correctif ou mesure d'atténuation | 90 jours au plus |
| Publication coordonnée de l'avis | Après le correctif, en accord avec vous |

Ces délais sont ceux d'un projet bénévole ; nous vous tiendrons informé en
cas de retard. Les personnes qui signalent une faille de bonne foi seront
remerciées dans l'avis, si elles le souhaitent.

## Périmètre

Sont notamment concernés : un lien analysé ouvert ou chargé sans action de
l'utilisateur, une fuite de contenu analysé (journaux, sauvegardes, réseau),
un verdict rassurant produit à tort par un défaut logique, une permission
injustifiée, une compromission de la chaîne de compilation ou de mise à
jour des listes.

Ne sont pas des vulnérabilités : une arnaque non détectée ou une fausse
alerte par les règles heuristiques (utilisez le modèle d'issue « Résultat
d'analyse contestable »).

## Versions prises en charge

Avant la v1.0, seule la dernière pré-version publiée reçoit des correctifs.
